0.3.2
  • Fixed: a double-click on a group could run a task. Expanding the group scrolls its children into view, and the task that ended up under the mouse pointer was run. A double-click now runs only the row it was aimed at.
  • Enter on a group, folder or module expands or collapses it, the same as a double-click there. On a task it still runs it.
  • Enter in the speed search runs the task it found right away and closes the search. It used to close the search first, so a second Enter was needed.
  • The tree uses the IDE's own icons — the same ones as the built-in Gradle view. The plugin no longer ships third-party icon files. Icons you set in the YAML configuration still take precedence.
0.3.1
  • Fixed: the tasks on root level were gone. A module node also carries the tasks of its subprojects — every name it does not define itself — and 0.3.0 dropped those rows as duplicates. In a build that applies its plugins centrally for all subprojects they are the only tasks the root project has, so its Tasks node stood empty. They are back, in italics and with a tooltip saying what that means.
  • Show Inherited Tasks in the toolbar switches them off again, like the toggle of the same name in the IDE's own Gradle view. On by default, and settable for the team with settings: showInheritedTasks:.
0.3.0
  • Enter runs the selected task, exactly as a double-click does — numpad Enter included. Only with a single task selected: a keystroke should not start several runs at once.
  • Rows you define yourself. An entry with execute inside a group's tasks becomes its own row that runs an existing Gradle task — no Gradle task is created, and neither the row name nor the group has to exist beforehand. Such a row is addressed by its own entry, so hiding the task it runs removes only the original occurrence.
  • Your own tooltips. Module, group and folder nodes show a tooltip when, and only when, a description entry gives them one. Tasks keep showing their Gradle description — previously they lent it to whatever node was drawn next.
  • The gear is a menu with Configuration and Reload. Reload re-reads both YAML files and the icons directory and rebuilds the view, so edited configuration and newly added icon files no longer need the project to be reloaded.
  • Task icons are grey instead of green, like the rest of the icon set. The tree is a list to browse, not a row of start buttons.
  • Fixed: task names and duplicates. The platform reports submodule tasks under their qualified name and hangs every module's tasks on its parent as inherited aggregates. Rows were therefore labelled :lib:printLibGui, identically named tasks of different modules collapsed into one, and running such a row started the task in every matching subproject. The aggregate rows themselves were removed as well — see 0.3.1, which brings them back properly.
