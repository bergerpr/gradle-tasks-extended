0.3.0
  • Rows you define yourself. An entry with execute inside a group's tasks becomes its own row that runs an existing Gradle task — no Gradle task is created, and neither the row name nor the group has to exist beforehand. Such a row is addressed by its own entry, so hiding the task it runs removes only the original occurrence.
  • Your own tooltips. Module, group and folder nodes show a tooltip when, and only when, a description entry gives them one. Tasks keep showing their Gradle description — previously they lent it to whatever node was drawn next.
  • The gear is a menu with Configuration and Reload. Reload re-reads both YAML files and the icons directory and rebuilds the view, so edited configuration and newly added icon files no longer need the project to be reloaded.
  • Task icons are grey instead of green, like the rest of the icon set. The tree is a list to browse, not a row of start buttons.
  • Fixed: task names and duplicates. The platform reports submodule tasks under their qualified name and hangs every module's tasks on its parent as inherited aggregates. Rows were therefore labelled :lib:printLibGui, every task appeared a second time under the root project, identically named tasks of different modules collapsed into one, and running such a duplicate started the task in every matching subproject.
